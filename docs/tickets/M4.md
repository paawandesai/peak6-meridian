## M4-04 · Red-team pass and security fixes
**Parallel-safe:** no (may touch any part of the codebase)
**Context:** plan.md M4 exit requires no open critical/high findings. Red-team per threat-model.md rules: local validator and devnet staging only, never third-party APIs or mainnet.
**Satisfies:** closure of critical/high security findings
**Build:** Red-team session: attempt each AB in threat-model.md against the local stack and devnet staging; probe for unlisted attack vectors (e.g. transaction size limits, compute budget exhaustion, edge-case arithmetic, data-source response injection, wallet-adapter edge cases). Document every finding with ID, severity, repro, and linked AB. For each critical/high finding: fix with a regression test in `tests/security/{program,ts,py}/` and verify the fix with a re-attack. New ABs are proposed in the MR description for the human to add to threat-model.md (human-owned, never edited directly). Medium/low findings may be documented in docs/risks.md as known limitations if fixing them is out of scope for M4.
**Acceptance criteria:**
- [ ] AC1 Every AB-01 through AB-22 has been tested against the final build (local validator or devnet); test log in MR with pass/fail per AB.
- [ ] AC2 No open critical findings: any critical finding discovered is either fixed with a regression test in this MR, or escalated to the human as a blocker.
- [ ] AC3 No open high findings: any high finding is fixed with a regression test, or documented in docs/risks.md with human approval and the `risk-accepted` label on the MR.
- [ ] AC4 Every fix has a regression test in `tests/security/` named after its AB ID (e.g. `ab_23_new_finding.test.ts` if a new AB-23 is discovered). New ABs proposed in MR description for human to add to threat-model.md (human-owned).
- [ ] AC5 Red-team log includes: each AB attempted, tool/script used, outcome (safe as expected / finding), and for findings the repro steps and fix commit.
**Verification:** Red-team log in MR; `make test-security` green; no critical/high findings in docs/status.md.
**Dependencies:** M3 merged (ops-agent and quant services deployed and testable).
**Files likely touched:** `tests/security/{program,ts,py}/**`, any file with a security fix, `docs/risks.md` (if accepted risks documented), `docs/status.md` (findings log).
