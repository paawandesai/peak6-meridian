## M3-01 · Fair-value engine and `/fair-values` service
**Context:** Differentiator A. Price each strike like a desk (domain.md § Fair value).
**Satisfies:** FR-24 · US-15 (engine)
**Build:** `services/quant` (Python 3.12, uv): `fair_value.py` computes fair_yes = N(d2) with r = 0, T = remaining regular-session seconds / (252 × 6.5 × 3600), σ = annualized 20-day realized vol of daily closes floored at 15%, T ≤ 0 → 1 if S ≥ K else 0; output integer cents clamped to [1, 99]. Live S from the same providers as M2-05 (server-side keys, fixtures in tests). HTTP `GET /fair-values` (bearer `SERVICE_TOKEN`) → `[{market, ticker, strike_cents, fair_cents, sigma, spot, as_of}]` per architecture.md. pydantic at every boundary, `httpx` with timeouts, `Decimal` for money, `mypy --strict`.
**Acceptance criteria:**
- [ ] AC1 hypothesis: fair is monotone non-increasing in K, in [1, 99], and the T→0 limit matches the step function.
- [ ] AC2 Golden values vs a reference N(d2) for 5 fixed cases (tolerance ±1¢ after rounding).
- [ ] AC3 σ floor and 20-day window tested from fixture closes; missing data → explicit error, no default σ.
- [ ] AC4 `/fair-values` rejects missing or invalid bearer; stale spot (> 10 s) is flagged `stale: true`.
- [ ] AC5 Coverage ≥ 80% (`services/quant`).
**Dependencies:** M2-05 (provider client patterns), M1-08 (calendar for T).
**Files:** `services/quant/src/meridian_quant/{fair_value,vol,prices,server}.py`, `services/quant/tests/**`.

## M3-02 · Market-maker loop (two-sided quotes on every open strike)
**Context:** US-16; plan exit "≥ 95% of open strikes two-sided over 30 min".
**Satisfies:** FR-25 · US-12, US-16 · AB-09, AB-10
**Build:** `services/quant/mm/`: per open strike, mint inventory via `mint_pair`, quote fair ± 2¢, size 10 per side, |inventory| ≤ 200 per strike, skew 1¢ per 50 contracts, pull all quotes if spot data is > 10 s old or < 2 min to close (domain.md § Market maker defaults). Uses `MARKET_MAKER_KEYPAIR` (server-only), `solders`/`solana-py`, `settle_funds` to recycle proceeds. A `book_coverage` metric (share of open strikes with a two-sided quote) is exposed on `/health`.
**Acceptance criteria:**
- [ ] AC1 Local validator: with M3-01 fair values, every open strike gets a bid and an ask within one loop.
- [ ] AC2 Inventory cap, skew and both pull rules (stale data, final 2 min) tested with a fake clock and fake fair values.
- [ ] AC3 `tests/security/py/ab_10_mm_limits.py`: the MM never exceeds the per-owner resting-order cap (8) or the inventory cap; prices always in 1–99.
- [ ] AC4 `book_coverage` computed correctly from a recorded book fixture (property test).
- [ ] AC5 No key material in logs (test); coverage ≥ 80%.
**Dependencies:** M3-01; M1-05/M1-06 (on-chain), M2-01 (deploy, for live).
**Files:** `services/quant/src/meridian_quant/mm/**`, `services/quant/tests/mm/**`, `tests/security/py/ab_10_mm_limits.py`.

## M3-05 · Ops agent: live investigation, incident note and validated override draft
**Context:** Differentiator C (D-021, D-025). Builds on the M1-11 safety layer.
**Satisfies:** FR-27 · US-17 · NFR-04 (override path), NFR-11 · AB-14, AB-15, AB-20
**Build:** `services/ops-agent`: HTTP `POST /incidents` and `GET /drafts` (bearer `SERVICE_TOKEN`) per architecture.md; JSON file store on the volume. `investigate()` uses read-only tools: fetch each source's close (provider clients, fixtures in tests), read market/oracle accounts, NYSE calendar. It produces an incident note (per-source prices, spread, staleness, calendar check) and an `OverrideDraft` validated by `validate_draft`. `LLMClient` backed by the `anthropic` SDK with model from `OPS_AGENT_MODEL` and spend logged against `OPS_AGENT_BUDGET_USD`; falls back to a deterministic note (source table + median, no narrative) when the API is unavailable or over budget. Never holds or reads key material; never signs.
**Acceptance criteria:**
- [ ] AC1 The M1-11 eval suite still passes 100% with the scripted fake LLM in CI (`uv run pytest services/ops-agent/evals`).
- [ ] AC2 Recorded-fixture incident → draft within the source range; out-of-range or URL/key-bearing drafts rejected (tests).
- [ ] AC3 Deterministic fallback used when the LLM fails or the budget is exhausted (tests); spend logged per call.
- [ ] AC4 No dependency able to sign Solana transactions and no keypair env reads (M1-11 AC3 test still passes).
- [ ] AC5 Endpoints reject missing/invalid bearer; coverage ≥ 80%. No live Anthropic calls in tests (`make eval-live` stays manual).
**Dependencies:** M1-11.
**Files:** `services/ops-agent/src/meridian_ops_agent/{agent,tools,llm,store,server}.py`, `services/ops-agent/tests/**`.
